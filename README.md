# SmartLab: Industrial Traceability

🇺🇸 English | 🇧🇷 [Português](README.pt-BR.md)

The system was developed as part of an assessment for the Signal Analysis and Processing course to automate the creation and organization of SPDA (Lightning Protection System) inspection points, using Bash and Google Drive cloud storage without requiring a web application. It automatically generates the directory structure for inspection files and QR Codes linked to each physical inspection point, facilitating mapping, access, and information recording during field activities.

The project follows the principle that the simplest solution is the best solution. The resulting system and directory structure (excluding images) use so little storage that they could fit on a floppy disk or even multiple times on a NES cartridge.

## System Layers

The system is divided into three main layers:

### 1. Configuration Layer

The `config_pontos.csv` file contains the parameters used to generate the inspection points, including:

* Client
* Facility
* Area
* Structure type
* Abbreviations
* Descriptions

The user defines the desired number of points for each combination of **area and equipment type** in this file.

---

### 2. Processing Layer

The `gerar_pontos.sh` script acts as the system's **instance generator**, interpreting the data from the `.CSV` file and creating the directory tree.

---

### 3. Persistence Layer

The root directory `SPDA_Pontos/` stores the entire structure generated by the system.

Each inspection point has its own dedicated folder, following a naming convention based on the registered information.

Example:

```text
[ClientAbbreviation]-[AreaAbbreviation]-[TypeAbbreviation]-[FacilityAbbreviation]
```

---

# Automatic Point Generation

The process begins by filling out the:

```text
config_pontos.csv
```

After the main script is executed, three steps are performed.

### 1. Data Validation

The system checks the integrity of the input data, ensuring that required fields are properly filled and that quantity values are **numeric and valid**.

### 2. Directory Structure Creation

For each CSV record, the system calculates the number of points and automatically creates their respective folders.

### 3. Field Asset Generation

The following files and directories are automatically created inside each folder:

| File/Directory  | Purpose                                           |
| --------------- | ------------------------------------------------- |
| `ponto.txt`     | Technical record containing the point's metadata  |
| `inspecoes.csv` | Inspection history                                |
| `fotos/`        | Storage for images and photographic records       |

The `inspecoes.csv` file is created with the necessary headers for recording inspection data, such as:

* Inspector/Responsible Person
* Visual Condition
* Measurements
* Observations
* Other Technical Data

---

# QR Code Generation

To facilitate the identification of physical inspection points, the system uses the **`qrencode`** command-line tool.

During execution, the script identifies newly created folders and automatically generates a:

```text
QR.png
```

Each QR Code contains a **public URL pointing directly to the folder corresponding to the inspection point**.

---

# Field Workflow

The workflow is simplified to facilitate the technician's inspection activities.

### 1. Identification

The technician scans the **QR Code** installed at the physical SPDA inspection point using a smartphone.

### 2. Access

The device automatically opens the folder in a web browser.

### 3. Inspection Recording

The technician accesses the:

```text
inspecoes.csv
```

file and records the information from the new inspection.

### 4. Update

After entering the data, the updated file is uploaded back to the same folder. This keeps the inspection history centralized and accessible to the team responsible for maintenance.

# FAQ

### Can the system use Microsoft OneDrive instead of Google Drive?

**Yes.**

One of the main characteristics of the solution is its **simplicity and ease of adaptation**. Since the system uses files and directories as its storage foundation, the main change required would be how the links are generated by the script.

Currently, the system uses Google Drive URLs, such as:

```text
https://drive.google.com/...
```

In an implementation using OneDrive, the links could point to:

```text
https://onedrive.live.com/...
```
---

### Can two different companies use the system?

**Yes.**

The system does not depend on a centralized database. Therefore, each company can have its own independent storage structure. Each company can keep its data isolated within its own storage environment, reducing the risk of information being mixed between organizations.
